# 本体与旋转底座固件修复记录

本次修改作用于 `F:\WorkSpace\VSCodeSpace\esp-echo-ear-xiaozhi` 和同级 `esp-echoear-base\software\echoear_rotating_base`。硬件接口、引脚、麦克风间距、原有声学角度补偿与用户已有业务代码修改保持不变。

## 修复

- 本体校准事件统一为开始 0x11、中间步骤 0x12、完成 0x13；完成信号在发出校准请求前清空，避免丢失快速响应。
- 本体检查接收数据长度、显示类型与 UART 写入结果；角度限定为 0–180。
- 底座 UART 保留半帧、解析连续多帧并校验完整 8 字节，错误长度和校验错误后重新同步。
- 底座收包与电机执行分离；动作队列容量 8，满时明确记录丢弃。角度使用单元素最新值队列，完成运动后丢弃基于旧麦克风姿态的待执行角度。
- 底座启动回零在远程控制启动前同步完成；限位按键只注册一次。
- DOA 使用项目本地 override，避免直接修改 managed_components。
- DOA 短读累计到完整音频帧后处理；滤波收满七个真实估计才输出，消除启动时零值偏差。
- DOA 从 20 度分桶改为 5 度就近量化，保留准确的 90 度中心；输出变化阈值为 5 度，间隔仍为一秒，讲话片段中断超过 500ms 后重置跟踪历史。
- DOA 回调确认模式、VAD、本体播音状态、角度有限且有效；正前方 5 度内不转动；只接收双通道、完整 int16 样本。

## 验证

- ESP-IDF 5.5.4：本体 ESP32-S3 `idf.py build` 成功，底座 ESP32-C61 `idf.py build` 成功。
- 实际底座 C 解析循环编译为临时 Windows DLL：15 项回归通过，覆盖所有帧内拆分点、逐字节输入、粘包、噪声、坏校验、错误长度、截断、非法角度和 100 帧连续输入。测试只替换 UART/队列输出，不执行电机。
- 实际 DOA C 量化函数：721 个 0–180 度测试通过，输出始终有效且误差不超过 2.5 度，中点保持 90 度。标准数学辅助函数在本机测试中用等价实现替代。
- 脚本：`python scripts/test_base_integration.py`，依赖本机 Visual Studio C 编译工具；测试不是实际麦克风定位精度验证。
- 未烧录，未运行真实电机，未执行真实模型。

## 仍需注意

- OTA 容量问题已在独立分支修复，详见 ISOLATED_BUILD_2026-10-12.md；实际设备 OTA 尚未验证。
- 底座原有 `magnetic_slide_switch_start()` 被用户注释；本次保留。因此磁滑块事件和真实磁校准尚不可用，校准请求会等待超时。
- 继续改进 DOA 需要双通道原始录音和真实角度标注：检查采样同步、通道增益/延时、46mm 默认间距与实际间距；验证现有非线性补偿和边缘角度偏置。没有录音证据时不调整这些参数。
- 双麦克风原理上有前后方歧义，滤波不能消除此限制；当前仅处理 0–180 度方向。转动方向、抗回声、噪声抖动和闭环收敛需设备实测。
